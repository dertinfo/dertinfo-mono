# Website upgraded from Angular 20 to Angular 21

## Summary of the work completed

The website (`apps/dert-web`) now builds and runs on Angular **21.2.25**, CLI **21.2.24**, and Angular Material / CDK **21.2.14**. The Ionic app is unchanged. `npm install` in `apps/dert-web/src/client` succeeds without `force`, and `npm run build:hosted` succeeds. The existing website smoke suite passed on Angular 21.2.25.

Nothing had to move before `ng update`. Node 20.20.2 and RxJS **6.6.7** were already inside the Angular 21 ranges. `ng update` moved TypeScript from **5.8.3** to **5.9.3** and left `zone.js` at **0.15.1**. `ngx-cookie-service` moved from 20.1.1 to **21.3.1**, and `ng2-file-upload` from 9.0.0 to **10.0.0**, because those peers named Angular 20. `@ngbracket/ngx-layout` stayed at **16.1.3** and `ng2-charts` at **5.0.4**. Their peers are `>=16`, and the production build accepted them.

The optional application-builder and `router-current-navigation` migrations were not run. The webpack `browser` builder stayed, `*ngIf` / `*ngFor` / `*ngSwitch` stayed, and `APP_INITIALIZER` stayed. A required bootstrap migration added `provideZoneChangeDetection()` on `bootstrapModule` in `main.ts`. A required CLI migration removed the `tsconfig.json` `lib` array. `target` is still `es2020`. The control-flow migration ran and rewrote 111 templates. Those template edits were restored.

The lockfile stays `lockfileVersion` 3, written by npm 10.8.2 on Node 20.20.2. The Dockerfile's global CLI pin is `@angular/cli@21`. The image base stays `node:20-bookworm`. Host-tooling notes in `docs/technical/infra/configuration.md` now say the website CLI is 21. The Node range is unchanged: `^20.19.0`, `^22.12.0`, or `>=24.0.0`.

## Why the work was completed

This is the seventh hop from Angular 14 toward a current Angular. The aim was the same as the earlier hops: one major, a healthy dependency tree, and the smallest application change that still installs and builds.

The 19 to 20 notes listed Node **20.20.2** and RxJS **6.6.7** as already inside the Angular 21 range, TypeScript **5.8.3** as too old, and `ngx-cookie-service` and `ng2-file-upload` as the peers that had to move with the major. Checked against the [version compatibility](https://angular.dev/reference/versions) table, that was right. There was no engine change to make on Angular 20 first. `ng update` moved TypeScript and did not move `zone.js`.

The application builder, standalone conversion, typed forms, zoneless change detection, and Material 3 were left. Angular 21 runs the control-flow migration during `ng update`. The template rewrite was reverted so the structural directives stay. They are deprecated and still compile. `provideZoneChangeDetection()` is the migration that keeps today's Zone behaviour after the scheduler default changes. It is not a move to zoneless.

## Issues that were encountered on the way

- This machine's default Node is 24. nvm-windows is not installed. Update, install, `ng build`, and `ng serve` used a portable Node **20.20.2** (npm 10.8.2). Node 20 reached end of life on 30 April 2026. The Static Web Apps proxy already listening on port 44200 stayed up. CI (`web-src-ci.yml`, `web-src-cd.yml`) and the website image stay on Node 20. The Ionic app and its CI stay on Node 16.
- `ng update @angular/cli@21 @angular/core@21` and `ng update @angular/material@21` completed with no `--force`. The second command needed `--allow-dirty` because the first update was not committed yet. The CLI listed `use-application-builder` and `router-current-navigation` as optional and did not run them. The control-flow migration is no longer optional. It rewrote 111 templates. Those files were restored, so `*ngIf`, `*ngFor`, and `*ngSwitch` stayed. The webpack `browser` builder stayed. `APP_INITIALIZER` stayed.
- The bootstrap migration added `provideZoneChangeDetection()` as `applicationProviders` on `platformBrowserDynamic().bootstrapModule` in `main.ts`. `src/polyfills.ts` still imports `zone.js`. The Material migration made no source changes.
- The CLI migration removed `lib` (`es2016` and `dom`) from `tsconfig.json`. That is what the migration does when the array contains DOM and an ES version of 2022 or older. `target` stayed `es2020`. `moduleResolution` stayed `bundler`. The production build still warns that the CLI applies ES2022 itself.
- `scroll-to.directive.ts` did not compile. `@HostListener('click', ['$event'])` passed an argument into `smoothScroll()`, which takes none. The unused argument was removed.
- `ng update` installed the packages even though `ng2-file-upload` 9 peers `@angular/common` `^20`. A later `npm install` failed on that peer. It moved to **10.0.0**. The published peer is `@angular/core` and `@angular/common` `^21.x.x`, and that installed against 21.2.25. It does not peer `jest-preset-angular`. `ngx-cookie-service` moved to **21.3.1**, which peers `^21.0.0`. Version 22.0.0 peers `^22` and was not taken. After that, `npm install` succeeded with no peer errors. `@ngbracket/ngx-layout` 16.1.3 and `ng2-charts` 5.0.4 peer `>=16` and stayed. The production build compiled them.
- The production build still warns that the theme is not the color/typography/density map. It also warns that some Browserslist entries fall outside Angular 21's browser support (`and_qq 14.9`, `and_uc 15.5`, `android 154`, `chrome 109`, `kaios 3.0-3.1`, `op_mob 80`, `opera 135`, `opera 134`, `samsung 30`, `samsung 29`). `chrome 109` is new on this hop. The ES5 entries (`kaios 2.5`, `op_mini all`) are still ignored. `.browserslistrc` was left as it was. `entryComponents` is still set on `AppLoaderModule`. The build accepts it.
- Material 21 marks the selected step with `aria-current="step"`. `aria-selected` and `aria-posinset` are gone. The header id ends `-label-N`. The smoke helpers now wait on that. The first activities click after the selector change timed out once. The following full run passed.
- The first smoke invocation looked for Playwright under an empty cache path. The suite was run again with the browsers already under `%LOCALAPPDATA%\ms-playwright`.

## References to any best practices that we found

- [Angular version compatibility](https://angular.dev/reference/versions) — Angular 21.0–21.2 support Node `^20.19.0 || ^22.12.0 || ^24.0.0`, TypeScript `>=5.9.0 <6.0.0`, and RxJS `^6.5.3 || ^7.4.0`. The installed CLI 21.2.24 engines field is `^20.19.0 || ^22.12.0 || >=24.0.0`. Angular 22.0 supports Node `^22.22.3 || ^24.15.0 || ^26.0.0` and TypeScript `>=6.0.0 <6.1.0`.
- [Angular v21](https://github.com/angular/angular/releases/tag/21.0.0) — Zone change detection is no longer scheduled unless `provideZoneChangeDetection` is provided. `ng update` adds that provider.
- [Migrating to the new build system](https://angular.dev/tools/cli/build-system-migration) — the application builder migration is still optional. Projects can keep the webpack `browser` builder.
- [ngx-cookie-service 21.3.1](https://www.npmjs.com/package/ngx-cookie-service/v/21.3.1) peers `@angular/core` `^21.0.0`. Version 22.0.0 peers `^22`.
- [ng2-file-upload 10.0.0](https://www.npmjs.com/package/ng2-file-upload/v/10.0.0) peers `@angular/core` and `@angular/common` `^21.x.x`.

## Any remaining issues that we may wish to address

- Angular 22 drops Node 20 (`^22.22.3 || ^24.15.0 || ^26.0.0`) and needs TypeScript `>=6.0.0 <6.1.0`. This site is on Node **20.20.2** and TypeScript **5.9.3**. RxJS **6.6.7** is inside the Angular 22 range (`^6.5.3 || ^7.4.0`). The next hop has to move Node before `ng update`. Let `ng update` move TypeScript.
- Node 20 is past end of life. Angular 21 still lists it, so this hop stayed on the line CI and the website image already use.
- `ngx-cookie-service` **21.3.1** peers `^21`. It must be bumped with the next Angular major. Version **22.0.0** peers `^22`. `ng2-file-upload` **10.0.0** peers `^21`. No later major was published on this hop. `ng update` does not carry either package.
- `@ngbracket/ngx-layout` **16.1.3** and `ng2-charts` **5.0.4** peer `>=16`. They did not have to move for Angular 21. Confirm them again on the next hop before treating a newer major as required.
- The application builder was not adopted. The webpack builder is deprecated and still supported. `APP_INITIALIZER` was not replaced. The control-flow migration ran and the template edits were restored. `*ngIf`, `*ngFor`, and `*ngSwitch` are deprecated and still compile.
- The Material theme still uses the Material 2 helpers (`m2-define-light-theme` / `m2-define-dark-theme`), plus `mat.elevation-classes()` and `mat.app-background()`. The build warns that the theme is not the color/typography/density map, and that some Browserslist entries are outside Angular 21's browser support. Material 3 was not adopted. Competition admin, Dert of Derts, notifications, and system admin were not part of the layout pass.
- Standalone components, typed forms, and zoneless change detection were not adopted. The `standalone: false` flags stay until a later conversion. This site stays on `zone.js` **0.15.1**, with `provideZoneChangeDetection()` on `bootstrapModule`. `moduleResolution` is `bundler`. `tsconfig.json` has no `lib` array.
- `entryComponents` remains on `AppLoaderModule`. The commented dashboard chart still uses the Chart.js 2 inputs.
- These packages are still referenced and were left in place: `angular-csv-ext`, `hopscotch`, `perfect-scrollbar`, `moment`, `tslint`, `codelyzer`. TSLint-to-ESLint is separate work. `@ngx-translate/core` 14, `@ngx-translate/http-loader` 7, `@swimlane/ngx-datatable` 20.1.0, and `@auth0/auth0-angular` 2.2.3 still install because their peers are an open `>=` range.
