# Website upgraded from Angular 21 to Angular 22

## Summary of the work completed

The website (`apps/dert-web`) now builds and runs on Angular **22.2.1**, CLI **22.2.1**, and Angular Material / CDK **22.2.1**. The Ionic app is unchanged. `npm install` in `apps/dert-web/src/client` succeeds without `force`, and `npm run build:hosted` succeeds. The existing website smoke suite passed on Angular 21.2.25 after the Node move, and again on Angular 22.2.1.

One stop was cleared while the site was still on Angular 21.2.25. Website CI and the website Docker image moved from Node 20 to Node 22. Node 22.23.3 is inside both the Angular 21 range (`^22.12.0`) and the Angular 22 range (`^22.22.3`). `ng update` moved TypeScript from **5.9.3** to **6.0.3** and left `zone.js` at **0.15.1** and RxJS at **6.6.7**. `ngx-cookie-service` moved from 21.3.1 to **22.0.0**, and `ng2-file-upload` from 10.0.0 to **11.0.0**, because those peers named Angular 21. `@ngbracket/ngx-layout` stayed at **16.1.3** and `ng2-charts` at **5.0.4**. Their peers are `>=16`, and the production build accepted them.

The optional application-builder and Karma-to-Vitest migrations were not run. The webpack `browser` builder stayed, `*ngIf` / `*ngFor` / `*ngSwitch` stayed, and `APP_INITIALIZER` stayed. A required migration added `ChangeDetectionStrategy.Eager` on 208 components. A required migration added `withXhr()` on `provideHttpClient`. Nine templates gained `$safeNavigationMigration(...)`. `RouterModule.forRoot` sets `paramsInheritanceStrategy: 'emptyOnly'`. `tsconfig.json` sets `strict: false`, `esModuleInterop: false`, and `ignoreDeprecations: "6.0"`. `target` is still `es2020`.

The lockfile stays `lockfileVersion` 3, written by npm 10.9.9 on Node 22.23.3. The Dockerfile's global CLI pin is `@angular/cli@22`. The image base is `node:22-bookworm`. Host-tooling notes in `docs/technical/infra/configuration.md` now say the website CLI is 22 and that website `ng` needs Node `^22.22.3`, `^24.15.0`, or `>=26.0.0`.

## Why the work was completed

This is the eighth hop from Angular 14 toward a current Angular. Angular 22 is the current major. The aim was the same as the earlier hops: one major, a healthy dependency tree, and the smallest application change that still installs and builds.

The 20 to 21 notes listed Node 20 and TypeScript **5.9.3** as outside the Angular 22 range, RxJS **6.6.7** as inside it, and `ngx-cookie-service` as a peer that had to move. They also said `ng2-file-upload` had no later major. Checked against the [version compatibility](https://angular.dev/reference/versions) table and the registry on this hop, the engine lines were right, and file-upload **11.0.0** had been published with an Angular 22 peer. Node moved to 22 before `ng update`, while the site was still on Angular 21. `ng update` moved TypeScript and did not move `zone.js`.

The application builder, standalone conversion, typed forms, signal forms, zoneless change detection, and Material 3 were left. The control-flow migration was not offered. `ChangeDetectionStrategy.Eager`, `withXhr()`, and `$safeNavigationMigration()` are the migrations that keep today's behaviour after the OnPush, Fetch, and optional-chaining defaults change. `paramsInheritanceStrategy: 'emptyOnly'` is the same kind of keep, written by hand because Angular ships no migration for it.

## Issues that were encountered on the way

- This machine's default Node is 24.19.0. nvm-windows is not installed. Update, install, `ng build`, and `ng serve` used a portable Node **22.23.3** (npm 10.9.9). Node **22.22.2** is below Angular 22's `^22.22.3` floor. The Static Web Apps proxy already listening on port 44200 stayed up. CI (`web-src-ci.yml`, `web-src-cd.yml`) and the website image are Node 22. The Ionic app and its CI stay on Node 16.
- A plain `npm install` on Node 22.23.3, before `ng update`, left the existing `lockfileVersion` 3 in place. The smoke suite then passed on Angular 21.2.25.
- `ng update @angular/cli@22 @angular/core@22` refused to start until `--force`, because `ng2-file-upload` 10 peers `@angular/common` `^21.x.x`, `ngx-cookie-service` 21 peers `^21.0.0`, and `codelyzer` peers Angular below 13. `--force` was used only to get the schematic through. `ng update @angular/material@22` needed `--allow-dirty` and the same `--force`. The CLI listed `use-application-builder` and `migrate-karma-to-vitest` as optional and did not run them. The control-flow migration was not in the list. The webpack `browser` builder stayed. `APP_INITIALIZER` stayed. The Material migration made no source changes.
- The core migration added `changeDetection: ChangeDetectionStrategy.Eager` on 208 components. The component that already set `OnPush` was left. It added `withXhr()` to `provideHttpClient(withInterceptorsFromDi())` in `app.module.ts`. It wrapped optional chaining in `$safeNavigationMigration()` in nine templates. It wrote `strictTemplates: false` and an `extendedDiagnostics` suppress into `src/tsconfig.app.json`. Those two settings together fail the build with `NG4003`. The suppress was removed. `strictTemplates` stays false.
- `paramsInheritanceStrategy` defaults to `'always'` and has no migration. `RouterModule.forRoot` now sets `paramsInheritanceStrategy: 'emptyOnly'`.
- `ng update` moved TypeScript to **6.0.3**. TypeScript 6 defaults `strict` and `esModuleInterop` to true, and it errors on deprecated `baseUrl` and `downlevelIteration` unless `ignoreDeprecations` is `"6.0"`. `tsconfig.json` sets `strict: false`, `esModuleInterop: false`, and `ignoreDeprecations: "6.0"`. `target` stayed `es2020`. `moduleResolution` stayed `bundler`. The production build still warns that the CLI applies ES2022 itself.
- `ng update` installed the packages with `--force` even though `ng2-file-upload` 10 peers `@angular/common` `^21.x.x` and `ngx-cookie-service` 21 peers `^21.0.0`. Those were then set to **11.0.0** and **22.0.0** in `package.json`. Version 11 peers `@angular/core` and `@angular/common` `^22.x.x`. The following `npm install` succeeded with no peer errors and no `.npmrc`. `@ngbracket/ngx-layout` 16.1.3 and `ng2-charts` 5.0.4 peer `>=16` and stayed. The production build compiled them. `codelyzer` stayed.
- The production build warns that `@angular-devkit/build-angular:browser` is deprecated with Webpack. It still warns that the theme is not the color/typography/density map, and that some Browserslist entries fall outside Angular's browser support (`and_qq 14.9`, `and_uc 15.5`, `android 154`, `chrome 109`, `kaios 3.0-3.1`, `op_mob 80`, `opera 135`, `opera 134`, `samsung 30`, `samsung 29`). That set is unchanged from Angular 21. The ES5 entries (`kaios 2.5`, `op_mini all`) are still ignored. `.browserslistrc` was left as it was. `entryComponents` is still set on `AppLoaderModule`. The build accepts it.

## References to any best practices that we found

- [Angular version compatibility](https://angular.dev/reference/versions) — Angular 22.0 supports Node `^22.22.3 || ^24.15.0 || ^26.0.0`, TypeScript `>=6.0.0 <6.1.0`, and RxJS `^6.5.3 || ^7.4.0`. The installed CLI 22.2.1 engines field is `^22.22.3 || ^24.15.0 || >=26.0.0`. Angular 21.2 supports Node `^20.19.0 || ^22.12.0 || ^24.0.0`.
- [Angular v22](https://github.com/angular/angular/releases/tag/22.0.0) — OnPush is the default change detection strategy. `Default` is renamed `Eager`. HttpClient uses Fetch unless `withXhr()` is provided. `paramsInheritanceStrategy` defaults to `'always'`.
- [Migrating to the new build system](https://angular.dev/tools/cli/build-system-migration) — the application builder migration is still optional. The webpack `browser` builder is deprecated and still runs.
- [Node.js 22.23.3](https://nodejs.org/en/blog/release/v22.23.3) ships npm 10.9.9. Node 22.22.2 is below Angular 22's floor.
- [ngx-cookie-service 22.0.0](https://www.npmjs.com/package/ngx-cookie-service/v/22.0.0) peers `@angular/core` `^22.0.0`.
- [ng2-file-upload 11.0.0](https://www.npmjs.com/package/ng2-file-upload/v/11.0.0) peers `@angular/core` and `@angular/common` `^22.x.x`.

## Any remaining issues that we may wish to address

- Angular 22 is the current major. A later major is not released, so this hop does not record an engine requirement for it.
- `ngx-cookie-service` **22.0.0** and `ng2-file-upload` **11.0.0** peer Angular 22. They have to be checked again when the next major exists. `ng update` does not carry them.
- `@ngbracket/ngx-layout` **16.1.3** and `ng2-charts` **5.0.4** peer `>=16`. They did not have to move for Angular 22. Confirm them again before treating a newer major as required.
- The application builder was not adopted. The webpack builder is deprecated and still runs. `APP_INITIALIZER` was not replaced. `*ngIf`, `*ngFor`, and `*ngSwitch` are deprecated and still compile.
- The Material theme still uses the Material 2 helpers (`m2-define-light-theme` / `m2-define-dark-theme`), plus `mat.elevation-classes()` and `mat.app-background()`. The build warns that the theme is not the color/typography/density map, and that some Browserslist entries are outside the browser set. Material 3 was not adopted. Competition admin, Dert of Derts, notifications, and system admin were not part of the layout pass.
- Standalone components, typed forms, signal forms, and zoneless change detection were not adopted. The `standalone: false` flags stay. Change detection stays `Eager` on the components that did not already set a strategy. The one `OnPush` component stays `OnPush`. HttpClient stays on XHR via `withXhr()`. This site stays on `zone.js` **0.15.1**, with `provideZoneChangeDetection()` on `bootstrapModule`. `moduleResolution` is `bundler`. `tsconfig.json` has no `lib` array. `strict` and `esModuleInterop` are explicitly false. `ignoreDeprecations` is `"6.0"` because `baseUrl` and `downlevelIteration` are deprecated in TypeScript 6.
- `entryComponents` remains on `AppLoaderModule`. The commented dashboard chart still uses the Chart.js 2 inputs.
- These packages are still referenced and were left in place: `angular-csv-ext`, `hopscotch`, `perfect-scrollbar`, `moment`, `tslint`, `codelyzer`. TSLint-to-ESLint is separate work. `@ngx-translate/core` 14, `@ngx-translate/http-loader` 7, `@swimlane/ngx-datatable` 20.1.0, and `@auth0/auth0-angular` 2.2.3 still install because their peers are an open `>=` range.
