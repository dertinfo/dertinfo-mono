# Website upgraded from Angular 17 to Angular 18

## Summary of the work completed

The website (`apps/dert-web`) now builds and runs on Angular **18.2.14**, CLI **18.2.21**, and Angular Material / CDK **18.2.14**. The Ionic app is unchanged. `npm install` in `apps/dert-web/src/client` succeeds without `force`, and `npm run build:hosted` succeeds. The existing website smoke suite passed.

Nothing had to move before `ng update`. Node 18.20.8, TypeScript **5.4.5**, RxJS **6.6.7**, and `zone.js` **0.14.10** were already inside the Angular 18.2 ranges. `ng update` did not change TypeScript. `ngx-cookie-service` moved from 17.1.0 to **18.0.0**, and `ng2-file-upload` from 6.0.0 to **7.0.1**, because those peers named Angular 17. `@ngbracket/ngx-layout` stayed at **16.1.3** and `ng2-charts` at **5.0.4**. Their peers are `>=16`, and the production build accepted them.

The optional application-builder migration was not run. The webpack `browser` builder stayed. A required core migration replaced `HttpClientModule` in `AppModule` with `provideHttpClient(withInterceptorsFromDi())`. The Material migration renamed `define-palette`, `define-light-theme`, and `define-dark-theme` to the `m2-` names in the five theme files. `tsconfig.json` `target` is still `es2020`.

The lockfile stays `lockfileVersion` 3. The Dockerfile's global CLI pin is `@angular/cli@18`. Host-tooling notes in `docs/technical/infra/configuration.md` now say the website CLI is 18 and that website `ng` needs Node `^18.19.1`, `^20.11.1`, or `^22.0.0`.

## Why the work was completed

This is the fourth hop from Angular 14 toward a current Angular. The aim was the same as the earlier hops: one major, a healthy dependency tree, and the smallest application change that still installs and builds.

The 16 to 17 notes listed Node, TypeScript, and RxJS as already inside the Angular 18 range, and named `ngx-cookie-service` and `ng2-file-upload` as the peers that had to move with the major. Checked against the [version compatibility](https://angular.dev/reference/versions) table, that was right. There was no engine change to make on Angular 17 first.

The application builder, the new control flow, standalone components, typed forms, zoneless change detection, and Material 3 were left. Angular asks for the application builder during this update. The webpack builder is deprecated and still supported, so the prompt was declined. `*ngIf`, `*ngFor`, and `*ngSwitch` still work. Angular 20 is the hop that deprecates those three and runs the control-flow migration.

## Issues that were encountered on the way

- This machine's default Node is 24. The Angular 18 CLI does not run on it. nvm-windows is not installed. Update, install, `ng build`, and `ng serve` used a portable Node **18.20.8** (npm 10.8.2). The Static Web Apps CLI on this machine is still the Node 24 global.
- `ng update @angular/cli@18 @angular/core@18` and `ng update @angular/material@18` completed with no `--force`. The CLI listed `use-application-builder` as an optional migration and did not run it. The webpack `browser` builder stayed.
- The core migration removed `HttpClientModule` and added `provideHttpClient(withInterceptorsFromDi())` so the existing `HTTP_INTERCEPTORS` class still runs. The schematic also collapsed the `AppModule` decorator. That formatting was put back. The behavior change is the provider.
- `ngx-cookie-service` 17 peers `^17`, so it moved to 18.0.0. `ng2-file-upload` 6 peers `^17`. Version 7.0.0 also peers `jest-preset-angular`, which does not resolve, so the site took **7.0.1**. After that, `npm install` succeeded with no peer errors. `@ngbracket/ngx-layout` 16.1.3 and `ng2-charts` 5.0.4 peer `>=16` and stayed. The production build compiled them.
- The Material schematic renamed the Material 2 Sass helpers in the five theme files. `mat.core()` and `mat.all-component-themes()` stayed. The production build still warns that the theme is not the color/typography/density map.
- The Angular 18 schematic did not rewrite `tsconfig.json` `target`. It is still `es2020`. The CLI still prints that it applies ES2022 itself. Browserslist entries that need ES5 (`kaios 2.5`, `op_mini all`) are ignored. `entryComponents` is still set on `AppLoaderModule`. The build accepts it.
- The first smoke run failed before a browser opened. `PLAYWRIGHT_BROWSERS_PATH` pointed at an empty cache. The suite was run again with the installed Chromium under `%LOCALAPPDATA%\ms-playwright`.

## References to any best practices that we found

- [Angular version compatibility](https://angular.dev/reference/versions) — Angular 18.2 supports Node `^18.19.1 || ^20.11.1 || ^22.0.0`, TypeScript `>=5.4.0 <5.6.0`, and RxJS `^6.5.3 || ^7.4.0`. Angular 19.0 supports the same Node and RxJS ranges, and TypeScript `>=5.5.0 <5.7.0`.
- [Migrating to the new build system](https://angular.dev/tools/cli/build-system-migration) — the application builder migration is optional on Angular 18. Projects can keep the webpack `browser` builder.
- [Angular Material 18.0.0](https://github.com/angular/components/releases/tag/18.0.0) — Material 2 Sass helpers are renamed with an `m2-` prefix. `ng update` applies that rename.
- [ngx-cookie-service 18.0.0](https://www.npmjs.com/package/ngx-cookie-service/v/18.0.0) peers `@angular/core` `^18`.
- [ng2-file-upload 7.0.1](https://www.npmjs.com/package/ng2-file-upload/v/7.0.1) peers `@angular/core` `^18`. Version 7.0.0 also peers `jest-preset-angular`.

## Any remaining issues that we may wish to address

- Angular 19 needs TypeScript **5.5** or newer. This site is on **5.4.5**. Node 18 and RxJS **6.6.7** are still inside the Angular 19 range. Angular 20 drops Node 18. Node 24 remains outside the Angular 18 CLI range.
- `ngx-cookie-service` **18.0.0** and `ng2-file-upload` **7.0.1** peer `^18`. They must be bumped with the next Angular major. `ng2-file-upload` 8 peers `^19`. `ng update` does not carry them.
- `@ngbracket/ngx-layout` **16.1.3** and `ng2-charts` **5.0.4** peer `>=16`. They did not have to move for Angular 18. Confirm them again on the next hop before treating a newer major as required.
- The application builder was not adopted. Angular asks for it on this hop. The webpack builder is deprecated and still supported. The new control flow was not adopted. Angular 20 deprecates `*ngIf`, `*ngFor`, and `*ngSwitch` and runs that migration during `ng update`.
- The Material theme still uses the Material 2 helpers (`m2-define-light-theme` / `m2-define-dark-theme`), and the build warns that the theme is not the color/typography/density map. Material 3 was not adopted. Competition admin, Dert of Derts, notifications, and system admin were not part of the layout pass.
- Standalone components, typed forms, and zoneless change detection were not adopted.
- `entryComponents` remains on `AppLoaderModule`. The commented dashboard chart still uses the Chart.js 2 inputs.
- These packages are still referenced and were left in place: `angular-csv-ext`, `hopscotch`, `perfect-scrollbar`, `moment`, `tslint`, `codelyzer`. TSLint-to-ESLint is separate work. `@ngx-translate/core` 14, `@ngx-translate/http-loader` 7, `@swimlane/ngx-datatable` 20.1.0, and `@auth0/auth0-angular` 2.2.3 still install because their peers are an open `>=` range.
