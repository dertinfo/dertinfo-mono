# Website upgraded from Angular 15 to Angular 16

## Summary of the work completed

The website (`apps/dert-web`) now builds and runs on Angular **16.2.12**, CLI **16.2.16**, and Angular Material / CDK **16.2.14**. The Ionic app is unchanged. `npm install` in `apps/dert-web/src/client` succeeds without `force`, and `npm run build:hosted` succeeds. The existing website smoke suite passed.

Two stops were cleared while the site was still on Angular 15.2.10, then bumped again with the framework:

- `@angular/flex-layout` is replaced by `@ngbracket/ngx-layout` **16.1.3**. Eighteen modules import `FlexLayoutModule` from that package. The `fxLayout` templates are unchanged.
- `ng2-charts` 2.4.3 (View Engine) is replaced by `ng2-charts` **5.0.4** and `chart.js` **4.5.1**. Angular 16 removes `ngcc`. The judge range report uses the Chart.js 3 scale shape. The dashboard chart stays inside an HTML comment.

`ng update` also moved TypeScript from 4.8.4 to **5.1.6** and `zone.js` from 0.11.4 to **0.13.3**. `ng2-file-upload` moved from 4.0.0 to **5.0.0**, and `ngx-cookie-service` from 15.0.0 to **16.1.0**, because those peers named Angular 15. The core migration removed deprecated guard and resolver `implements` clauses from 31 files. The methods stayed.

CI and the website Docker image stay on Node 16. The lockfile remains `lockfileVersion` 2. The Dockerfile's global CLI pin is `@angular/cli@16`. Host-tooling notes in `docs/technical/infra/configuration.md` now say the website CLI is 16 and that website `ng` needs Node `^16.14` or `^18.10`.

## Why the work was completed

This is the second hop from Angular 14 toward a current Angular. The aim was the same as the first hop: one major, a healthy dependency tree, and the smallest application change that still installs and builds.

The 14 to 15 notes listed several leftovers as constraints on this hop. Checked against the [version compatibility](https://angular.dev/reference/versions) table, only two of them would stop Angular 16: flex-layout has no maintained 16 release, and `ngcc` is gone so a View Engine chart cannot compile. Those were replaced before `ng update`, on Angular 15, so a failed hop would not be the first time the layout or the chart moved. RxJS stayed on 6 because Angular 16 still allows it.

Standalone components, typed forms, the Material theme map, and the unfinished layout screens were left. They are not required to install Angular 16.

## Issues that were encountered on the way

- This machine's default Node is 24. The Angular 16 CLI does not run on it. Update, install, and `ng build` used a portable Node **16.20.2**. Node 18's npm can write `lockfileVersion` 3, so installs stayed on Node 16 to keep lockfile version 2. The Static Web Apps CLI requires Node 18 or newer, so the local proxy on port 44200 ran on Node 24 while `ng serve` used Node 16.
- `ng update @angular/cli@16 @angular/core@16` and `ng update @angular/material@16` completed with no `--force`. A following `npm install` of the layout fork and charts failed. `ng2-file-upload` 4 peers `@angular/common` `^15`. After that moved to 5.0.0, `ngx-cookie-service` 15 peers `^15`. After that moved to 16.1.0, `npm install` succeeded with no peer errors.
- `ng2-charts` 5.0.0 through 5.0.2 publish a `ng2-charts-schematics` peer that does not resolve on npm. **5.0.4** installs cleanly. Its peers are Angular `>=16` and RxJS `^6.5.3 || ^7.4.0`.
- `@ngbracket/ngx-layout` 16.1.3 allows RxJS `^6.5.3 || ^7.8.0`. The RxJS 7 side starts at 7.8, which is narrower than Angular's `^7.4.0`. RxJS 6.6.7 matches the 6 side, so RxJS was not moved.
- The Angular 16 schematic did not rewrite `tsconfig.json` `target`. It is still `es2020`. The CLI still prints that it applies ES2022 itself. Browserslist entries that need ES5 (`kaios 2.5`, `op_mini all`) are ignored.
- The production build still warns that the Material theme is not the v15 color/typography/density map. The palette is still `mat.define-light-theme($primary, $accent)`.
- No stylesheet still uses a `~` import. No source file imports `rxjs/Observable`. Imports from `rxjs/operators` are the supported path and were left.
- Nothing referenced `ReflectiveInjector`, `BrowserTransferStateModule`, `ComponentFactoryResolver`, or `router.navigate([], { relativeTo })`. `entryComponents` is still set on `AppLoaderModule`. The build accepts it.
- The first smoke run failed before opening a page because `PLAYWRIGHT_BROWSERS_PATH` pointed at a sandbox cache that had no Chromium. The browsers are already in the normal user cache. The suite was run again with that variable unset. That failure was not an application defect.

## References to any best practices that we found

- [Angular version compatibility](https://angular.dev/reference/versions) — Angular 16.2 supports Node `^16.14.0 || ^18.10.0`, TypeScript `>=4.9.3 <5.2.0`, and RxJS `^6.5.3 || ^7.4.0`. Angular 17.0 supports Node `^18.13.0 || ^20.9.0`, TypeScript `>=5.2.0 <5.3.0`, and the same RxJS range.
- [Update Angular to v16](https://v17.angular.io/guide/update-to-version-16) — Node 14 is dropped, TypeScript 4.9 is the floor, and `ngcc` is removed. View Engine libraries cannot be used.
- [ng2-charts Angular compatibility](https://www.npmjs.com/package/ng2-charts) — Angular 15 takes v3 or v4. Angular 16 takes v5. Releases 5.0.0–5.0.2 do not install cleanly; 5.0.4 does.
- [Modern CSS in Angular layouts](https://blog.angular.io/modern-css-in-angular-layouts-4a259dca9127) — `@angular/flex-layout` is deprecated. `@ngbracket/ngx-layout` continues the same directives and is bumped with the Angular major.

## Any remaining issues that we may wish to address

- Angular 17 requires Node 18 or newer. Node 16 remains valid here. CI and the website image are Node 16, and the lockfile is version 2. Moving Node can change the lockfile npm major.
- TypeScript **5.1.6** is the top of the Angular 16.2 range. Angular 17 needs 5.2 or newer. Leave that to `ng update`.
- RxJS stays at **6.6.7**. Angular 17 still allows that range. A newer `ngx-quill` is what would force RxJS 7. `@ngbracket/ngx-layout` 16.1.3's RxJS 7 peer starts at 7.8, so a move to RxJS 7.4 would not satisfy the fork.
- `@ngbracket/ngx-layout`, `ng2-charts`, `ng2-file-upload`, and `ngx-cookie-service` must be bumped with the next Angular major. `ng update` does not carry them.
- The Material theme still uses `define-light-theme($primary, $accent)`, and the build warns about it. Competition admin, Dert of Derts, notifications, and system admin were not part of the layout pass.
- Standalone components and typed forms were not adopted. The standalone schematic is available and was not run.
- `entryComponents` remains on `AppLoaderModule`. The commented dashboard chart still uses the Chart.js 2 inputs.
- These packages are still referenced and were left in place: `angular-csv-ext`, `hopscotch`, `perfect-scrollbar`, `moment`, `tslint`, `codelyzer`, `protractor` (`dertinfo-e2e`). TSLint-to-ESLint and dropping Protractor are separate work. `@ngx-translate/core` 14, `@ngx-translate/http-loader` 7, `@swimlane/ngx-datatable` 20.1.0, and `@auth0/auth0-angular` 2.2.3 still install because their peers are an open `>=` range.
- `npm install` prints engine warnings for `karma-cli@1.0.1` (declares Node 0.10–6) and a transitive `node-releases` package (wants Node 18). They are not peer failures.
