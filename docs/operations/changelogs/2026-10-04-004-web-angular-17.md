# Website upgraded from Angular 16 to Angular 17

## Summary of the work completed

The website (`apps/dert-web`) now builds and runs on Angular **17.3.12**, CLI **17.3.17**, and Angular Material / CDK **17.3.10**. The Ionic app is unchanged. `npm install` in `apps/dert-web/src/client` succeeds without `force`, and `npm run build:hosted` succeeds. The existing website smoke suite passed.

One stop was cleared while the site was still on Angular 16.2.12. Website CI and the website Docker image moved from Node 16 to Node 18, and `src/test.ts` stopped importing `zone.js/dist/*`. `ng update` then moved TypeScript from 5.1.6 to **5.4.5** and `zone.js` from 0.13.3 to **0.14.10**. `ng2-file-upload` moved from 5.0.0 to **6.0.0**, and `ngx-cookie-service` from 16.1.0 to **17.1.0**, because those peers named Angular 16. `@ngbracket/ngx-layout` stayed at **16.1.3** and `ng2-charts` at **5.0.4**. Their peers are `>=16`, and the production build accepted them.

The core migration escaped `@` as `&#64;` in five templates. `browserTarget` in `angular.json` became `buildTarget`. The webpack browser builder stayed. `@import '@angular/material/theming'` was removed from the five theme files because Material 17 does not publish that stylesheet. The themes still use `@use '@angular/material' as mat`.

Protractor, Karma, and Jasmine were removed from the website, including the `dertinfo-e2e` project, the unit-test specs, and the CI unit-test step. The Playwright suite in `tests/e2e` is the website test. The Ionic app's Protractor and Karma setup was left.

The lockfile is `lockfileVersion` 3, written by npm 10.8.2 on Node 18.20.8. The Dockerfile's global CLI pin is `@angular/cli@17`. Host-tooling notes in `docs/technical/infra/configuration.md` now say the website CLI is 17 and that website `ng` needs Node `^18.13` or `^20.9`.

## Why the work was completed

This is the third hop from Angular 14 toward a current Angular. The aim was the same as the earlier hops: one major, a healthy dependency tree, and the smallest application change that still installs and builds.

The 15 to 16 notes listed Node 16 and several packages as constraints on this hop. Checked against the [version compatibility](https://angular.dev/reference/versions) table, Angular 17.3 requires Node `^18.13.0 || ^20.9.0` and still allows RxJS 6. Node 18 is also inside the Angular 16.2 range, so the website moved to Node 18, and the zone test import was fixed, before `ng update`. A failed hop would not have been the first time those moved. RxJS stayed on 6 because Angular 17 still allows it.

`@ngbracket/ngx-layout` and `ng2-charts` were predicted as required bumps. Their peers are an open `>=16` range, so they were left. Only `ng2-file-upload` and `ngx-cookie-service` named Angular 16 exactly.

Standalone components, the new control flow, the application builder, typed forms, the Material theme map, and the unfinished layout screens were left. They are not required to install Angular 17.

## Issues that were encountered on the way

- This machine's default Node is 24. The Angular 17 CLI does not run on it. nvm-windows is not installed. Update, install, and `ng build` used a portable Node **18.20.8** (npm 10.8.2). A plain `npm install` on that Node kept the existing `lockfileVersion` 2. `npm install --lockfile-version 3` converted it. The Static Web Apps CLI on this machine is still the Node 24 global. `ng serve` used Node 18.
- `ng update @angular/cli@17 @angular/core@17` and `ng update @angular/material@17` completed with no `--force`. A following `npm install` failed. `ng2-file-upload` 5 peers `@angular/common` `^16`. It moved to 6.0.0. `ngx-cookie-service` 16 peers `^16`, so it moved to 17.1.0 in the same install. After that, `npm install` succeeded with no peer errors.
- `@ngbracket/ngx-layout` 16.1.3 and `ng2-charts` 5.0.4 peer Angular `>=16` and RxJS `^6.5.3` (the layout fork's RxJS 7 side starts at 7.8). Both stayed. The production build compiled them.
- `@import '@angular/material/theming'` failed. Material 17's package export points at a root `_theming.scss` that is not in the published package. The themes already `@use '@angular/material' as mat`, so the import was removed. The production build still warns that the Material theme is not the color/typography/density map. The palette is still `mat.define-light-theme($primary, $accent)`.
- The Angular 17 schematic did not rewrite `tsconfig.json` `target`. It is still `es2020`. The CLI still prints that it applies ES2022 itself. Browserslist entries that need ES5 (`kaios 2.5`, `op_mini all`) are ignored. `browserTarget` became `buildTarget`.
- The core migration escaped `@` in five templates so the new control flow parser does not treat those characters as syntax. The new control flow was not adopted.
- Nothing referenced `ReflectiveInjector`, `BrowserTransferStateModule`, `ComponentFactoryResolver`, `WritableSignal.mutate`, or `ngSwitch`. `entryComponents` is still set on `AppLoaderModule`. The build accepts it.
- Protractor, Karma, and Jasmine were removed from the website after the smoke suite passed. Website CI no longer runs `ng test`. The Ionic app still has its own Protractor and Karma setup.

## References to any best practices that we found

- [Angular version compatibility](https://angular.dev/reference/versions) — Angular 17.3 supports Node `^18.13.0 || ^20.9.0`, TypeScript `>=5.2.0 <5.5.0`, and RxJS `^6.5.3 || ^7.4.0`. Angular 18.0 supports Node `^18.19.1 || ^20.11.1 || ^22.0.0`, TypeScript `>=5.4.0 <5.5.0`, and the same RxJS range.
- [Angular 17.0.0 changelog](https://github.com/angular/angular/blob/17.0.x/CHANGELOG.md) — Node 16 is removed, TypeScript 5.2 is the floor, `zone.js` is `~0.14.0`, and `zone.js/dist/*` imports are removed.
- [ng2-file-upload 6.0.0](https://www.npmjs.com/package/ng2-file-upload/v/6.0.0) peers `@angular/core` `^17`. Version 5.0.0 peers `^16`.
- [ngx-cookie-service supported versions](https://www.npmjs.com/package/ngx-cookie-service) — Angular 17 takes 17.x. **17.1.0** peers `^17`.

## Any remaining issues that we may wish to address

- Angular 18.0 still allows this site's Node 18, TypeScript **5.4.5**, and RxJS **6.6.7**. Angular 19.0 needs TypeScript 5.5 or newer. Angular 20 drops Node 18. Node 24 remains outside the Angular 17 CLI range.
- `ngx-cookie-service` **17.1.0** and `ng2-file-upload` **6.0.0** peer `^17`. They must be bumped with the next Angular major. `ng update` does not carry them.
- `@ngbracket/ngx-layout` **16.1.3** and `ng2-charts` **5.0.4** peer `>=16`. They did not have to move for Angular 17. Confirm them again on the next hop before treating a newer major as required.
- RxJS stays at **6.6.7**. A newer `ngx-quill` is what would force RxJS 7. `@ngbracket/ngx-layout` 16.1.3's RxJS 7 peer starts at 7.8.
- The Material theme still uses `define-light-theme($primary, $accent)`, and the build warns about it. Competition admin, Dert of Derts, notifications, and system admin were not part of the layout pass.
- The application builder, control flow, standalone components, and typed forms were not adopted.
- `entryComponents` remains on `AppLoaderModule`. The commented dashboard chart still uses the Chart.js 2 inputs.
- These packages are still referenced and were left in place: `angular-csv-ext`, `hopscotch`, `perfect-scrollbar`, `moment`, `tslint`, `codelyzer`. TSLint-to-ESLint is separate work. `@ngx-translate/core` 14, `@ngx-translate/http-loader` 7, `@swimlane/ngx-datatable` 20.1.0, and `@auth0/auth0-angular` 2.2.3 still install because their peers are an open `>=` range.
