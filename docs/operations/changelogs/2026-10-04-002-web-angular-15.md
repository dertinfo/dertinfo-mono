# Website upgraded from Angular 14 to Angular 15

## Summary of the work completed

The website (`apps/dert-web`) now builds and runs on Angular **15.2.10**, CLI **15.2.11**, and Angular Material / CDK **15.2.9**. The Ionic app is unchanged. `npm install` in `apps/dert-web/src/client` succeeds without `force`, and `npm run build:hosted` succeeds. The existing website smoke suite passed.

Material stays on the legacy components. The official Material 15 update rewrote imports to `MatLegacy*` aliases and switched theme styles to `mat.legacy-core` / `mat.all-legacy-component-themes`. The MDC migration was not run.

`apps/dert-web/src/client/.npmrc` (`force = true`) is removed. The website Dockerfile installs with `npm install` and pins the global CLI at `@angular/cli@15`. CI and the Docker image stay on Node 16. The lockfile remains `lockfileVersion` 2.

## Why the work was completed

This is the first hop from Angular 14 toward a current Angular. The aim was a healthy dependency tree for this one major, with the smallest application change that still installs and builds. Packages nothing referenced were removed. Packages the site still uses were moved only to a release that declares Angular 15 (and, where it mattered, RxJS 6).

## Issues that were encountered on the way

- `ng update` refused to start until `--force` was passed, because `ngx-cookie-service` 13 and `ngx-quill` 15 do not peer Angular 15. The schematics were applied with that flag. After the package alignment below, a later `npm install` succeeded with no `force` and no peer errors.
- `ngx-quill` 18 and later, including the 20/21 line that peers Angular 15, require RxJS 7. RxJS was kept on 6. `ngx-quill` is **17.0.0**, which peers `@angular/core >=13` and `rxjs ^6.5.3 || ^7.4.0`.
- `@swimlane/ngx-datatable` 20.1.0 peers `rxjs ^6.6.3`. RxJS moved from **6.5.5** to **6.6.7** (still RxJS 6). Angular 15 accepts that range.
- The datatable styles used `@import "~@swimlane/ngx-datatable/..."`. Angular 15's resolver honours the package `exports` field, which does not export those CSS files. The three imports in `src/assets/styles/styles.scss` now use relative paths under `node_modules`. No other stylesheet used the `~` prefix.
- `rxjs-compat` had no import of that package name, but `group-members.component.ts` imported `Observable` from `rxjs/Observable`, which only the compat package provides. That one import now comes from `rxjs`, and `rxjs-compat` is removed.
- The Angular 15 CLI schematic set `tsconfig.json` `target` to `ES2022` and added `useDefineForClassFields: false`. Those edits were reverted. The CLI still prints that it applies those options itself and that browserslist controls the emitted language. Browserslist entries that need ES5 (`kaios 2.5`, `op_mini all`) are ignored. `.browserslistrc` and `src/polyfills.ts` were left as they were.
- Production build warns that the Material theme is not the v15 color/typography/density map. The legacy theme still compiles. It was not restyled.
- `ng2-charts` 2.4.3 is still a View Engine build (`ngcc` processes it). Its peer range is `@angular/core >=7.2.0`, so it was not upgraded. `chart.js` stays on 2.x.
- Angular CLI 15 does not run on Node 24. Update and `ng build` used Node **16.20.2**. The Static Web Apps CLI on this machine requires Node 18 or newer, so the local proxy on port 44200 was started with Node 24 while `ng serve` used Node 16. CI and Docker stay on Node 16, which is inside the Angular 15 range (`^16.13` or `^18.10`).
- The first smoke run failed before opening a page because Playwright looked for Chromium in a sandbox cache path. After installing Chromium into the normal user cache, the suite was run again. That failure was not an application defect.

## References to any best practices that we found

- [Angular version compatibility](https://angular.dev/reference/versions) — Angular 15.2 supports Node `^14.20 || ^16.13 || ^18.10`, TypeScript `>=4.8.2 <5.0`, and RxJS `^6.5.3 || ^7.4.0`.
- [Angular 15.0.0 release](https://github.com/angular/angular/releases/tag/15.0.0) — `enableIvy` and `relativeLinkResolution` are removed. Ivy was already the compiler; the flag was only deleted. Removing `relativeLinkResolution: 'legacy'` means relative links use the corrected resolution.
- [Migrating to MDC-based Angular Material](https://material.angular.io/guide/mdc-migration) — `ng update @angular/material@15` moves the app onto legacy components. Legacy components are removed in Material 17.
- [Modern CSS in Angular layouts](https://blog.angular.io/modern-css-in-angular-layouts-4a259dca9127) — `@angular/flex-layout` is deprecated. `15.0.0-beta.42` is the last release.

## Any remaining issues that we may wish to address

- Material legacy components must be migrated to MDC before Material 17. That changes DOM and CSS. It was intentionally not part of this hop.
- `@angular/flex-layout@15.0.0-beta.42` has no Angular 16 release. Replacing it is a later hop.
- Angular 16 requires RxJS 7. `ngx-quill` 18+ needs that same move. `@auth0/auth0-angular` stays at **2.2.3**; a newer 2.x can use Angular 15 APIs and was not required here.
- Angular 17 requires Node 18 or newer. Node 16 remains valid for this website. Local Node 24 cannot run the Angular 15 CLI.
- These packages are still referenced and were left in place: `angular-csv-ext`, `hopscotch`, `perfect-scrollbar`, `moment`, `ng2-charts` / `chart.js` 2, `tslint`, `codelyzer`, `protractor` (`dertinfo-e2e`). TSLint-to-ESLint and dropping Protractor are separate work. Web Src CI already treats lint and unit tests as `continue-on-error`.
- `npm install` prints engine warnings for `karma-cli@1.0.1` (declares Node 0.10–6) and a transitive `node-releases` package (wants Node 18). They are not peer failures.
- Standalone components and typed forms were not adopted.

### Packages removed because nothing referenced them
