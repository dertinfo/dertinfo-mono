# Change logs belong on the pull request

## Summary of the work completed

Opening a pull request now includes a change log for that work in the same PR in nearly all cases. If there is any doubt about leaving it off, ask before opening the PR without one. The instruction is in [`.cursor/rules/changelogs.mdc`](../../../.cursor/rules/changelogs.mdc), with a short reminder on the GitHub Flow and monorepo rules, and the same wording on the [change log index](./README.md), the [documentation guide](../../documentation-guide.md), and the [agents note](../agents/README.md).

## Why the work was completed

Pull request 60 merged without a change log because the previous rule waited until a workstream felt finished. The pull request is the work, so the entry belongs in that PR. Asking when it is unclear avoids skipping an entry by default.
