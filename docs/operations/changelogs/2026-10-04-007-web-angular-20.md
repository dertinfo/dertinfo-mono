# Website upgraded from Angular 19 to Angular 20

## Summary of the work completed

The website (`apps/dert-web`) now builds and runs on Angular **20.3.33**, CLI **20.3.37**, and Angular Material / CDK **20.2.14**. The Ionic app is unchanged. `npm install` in `apps/dert-web/src/client` succeeds without `force`, and `npm run build:hosted` succeeds. The existing website smoke suite passed on Angular 19.2.25 after the Node move, and again on Angular 20.3.33.

One stop was cleared while the site was still on Angular 19.2.25. Website CI and the website Docker image moved from Node 18 to Node 20. Node 20.20.2 is inside both the Angular 19.2 range (`^20.11.1`) and the Angular 20 range (`^20.19.0`). `ng update` left TypeScript at **5.8.3**, `zone.js` at **0.15.1**, and RxJS at **6.6.7**. `ngx-cookie-service` moved from 19.1.2 to **20.1.1**, and `ng2-file-upload` from 8.0.0 to **9.0.0**, because those peers named Angular 19. `@ngbracket/ngx-layout` stayed at **16.1.3** and `ng2-charts` at **5.0.4**. Their peers are `>=16`, and the production build accepted them.

The optional application-builder, control-flow, and `router-current-navigation` migrations were not run. The webpack `browser` builder stayed, `*ngIf` / `*ngFor` / `*ngSwitch` stayed, and `APP_INITIALIZER` stayed. A required CLI migration set `moduleResolution` to `bundler` and wrote schematic defaults that keep the current file-name suffixes. A required core migration moved the `DOCUMENT` import in `auth.service.ts` from `@angular/common` to `@angular/core`. `tsconfig.json` `target` is still `es2020`.

The lockfile stays `lockfileVersion` 3, written by npm 10.8.2 on Node 20.20.2. The Dockerfile's global CLI pin is `@angular/cli@20`. Host-tooling notes in `docs/technical/infra/configuration.md` now say the website CLI is 20 and that website `ng` needs Node `^20.19.0`, `^22.12.0`, or `>=24.0.0`.

## Why the work was completed

This is the sixth hop from Angular 14 toward a current Angular. The aim was the same as the earlier hops: one major, a healthy dependency tree, and the smallest application change that still installs and builds.

The 18 to 19 notes listed Node 18 as outside the Angular 20 range, TypeScript **5.8.3** and RxJS **6.6.7** as already inside it, and `ngx-cookie-service` and `ng2-file-upload` as the peers that had to move with the major. Checked against the [version compatibility](https://angular.dev/reference/versions) table, that was right. Node 20 is also inside the Angular 19.2 range, so the website moved to Node 20 before `ng update`. A failed hop would not have been the first time Node moved. `ng update` did not need to move TypeScript or `zone.js`. Angular 20.3 allows TypeScript `>=5.8.0 <6.0.0`.

The application builder, the control-flow rewrite, standalone conversion, typed forms, zoneless change detection, and Material 3 were left. Angular lists the application builder and the control-flow migration as optional. A non-interactive update skips them. `*ngIf`, `*ngFor`, and `*ngSwitch` are deprecated and still compile. The `standalone: false` flags from the Angular 19 hop stay.

## Issues that were encountered on the way

- This machine's default Node is 24. nvm-windows is not installed. Update, install, `ng build`, and `ng serve` used a portable Node **20.20.2** (npm 10.8.2). That is the last Node 20 release. Node 20 reached end of life on 30 April 2026. The Static Web Apps proxy already listening on port 44200 stayed on the Node 18.20.8 process from the previous hop. CI (`web-src-ci.yml`, `web-src-cd.yml`) and the website image are Node 20. The Ionic app and its CI stay on Node 16.
- A plain `npm install` on Node 20.20.2, before `ng update`, left the existing `lockfileVersion` 3 in place. The smoke suite then passed on Angular 19.2.25.
- `ng update @angular/cli@20 @angular/core@20` and `ng update @angular/material@20` completed with no `--force`. The second command needed `--allow-dirty` because the first update was not committed yet. The CLI listed `use-application-builder`, `control-flow-migration`, and `router-current-navigation` as optional migrations and did not run them. The webpack `browser` builder stayed. `APP_INITIALIZER` stayed. `provide-initializer` was not offered.
- The CLI migration set `tsconfig.json` `moduleResolution` from `node` to `bundler` and added `type` / `typeSeparator` schematic defaults in `angular.json` so new files keep the previous suffixes. `target` stayed `es2020`. The core migration moved `DOCUMENT` in `auth.service.ts` onto the `@angular/core` import. The `InjectFlags` and `TestBed.get` migrations made no changes. The Material migration made no source changes. It rewrote two files under `dist/`, which is gitignored.
- `ng update` installed the packages even though `ng2-file-upload` 8 peers `@angular/common` `^19`. A later `npm install` failed on that peer. It moved to **9.0.0**, which peers `@angular/core` `^20` and does not peer `jest-preset-angular`. `ngx-cookie-service` 19 peers `^19`. Version **20.0.0** still peers `^19`. Version **20.1.1** peers `^20`. After that, `npm install` succeeded with no peer errors. `@ngbracket/ngx-layout` 16.1.3 and `ng2-charts` 5.0.4 peer `>=16` and stayed. The production build compiled them.
- The production build still warns that the theme is not the color/typography/density map, and that the CLI applies ES2022 itself. It also warns that some Browserslist entries fall outside Angular 20's browser support (`and_qq 14.9`, `and_uc 15.5`, `android 154`, `kaios 3.0-3.1`, `op_mob 80`, `opera 135`, `opera 134`, `samsung 30`, `samsung 29`). The ES5 entries (`kaios 2.5`, `op_mini all`) are still ignored. `.browserslistrc` was left as it was. `entryComponents` is still set on `AppLoaderModule`. The build accepts it.

## References to any best practices that we found

- [Angular version compatibility](https://angular.dev/reference/versions) — Angular 20.2 and 20.3 support Node `^20.19.0 || ^22.12.0 || ^24.0.0`, TypeScript `>=5.8.0 <6.0.0`, and RxJS `^6.5.3 || ^7.4.0`. The installed CLI 20.3.37 engines field is `^20.19.0 || ^22.12.0 || >=24.0.0`. Angular 21.0–21.2 keeps that Node range and requires TypeScript `>=5.9.0 <6.0.0`.
- [Angular v20](https://github.com/angular/angular/releases/tag/20.0.0) — Node 18 is removed. `*ngIf`, `*ngFor`, and `*ngSwitch` are deprecated. `DOCUMENT` moves from `@angular/common` to `@angular/core`.
- [Migrating to the new build system](https://angular.dev/tools/cli/build-system-migration) — the application builder migration is still optional. Projects can keep the webpack `browser` builder.
- [ngx-cookie-service 20.1.1](https://www.npmjs.com/package/ngx-cookie-service/v/20.1.1) peers `@angular/core` `^20`. Version 20.0.0 still peers `^19`.
- [ng2-file-upload 9.0.0](https://www.npmjs.com/package/ng2-file-upload/v/9.0.0) peers `@angular/core` `^20`. Version 10 peers Angular 21.
- [Node.js 20.20.2](https://nodejs.org/en/blog/release/v20.20.2) is the last Node 20 release. The 20 line ended on 30 April 2026.

## Any remaining issues that we may wish to address

- Angular 21 needs TypeScript `>=5.9.0 <6.0.0`. This site is on **5.8.3**. Node **20.20.2** and RxJS **6.6.7** are inside the Angular 21 range (`^20.19.0 || ^22.12.0 || ^24.0.0` and `^6.5.3 || ^7.4.0`). Let `ng update` move TypeScript. Angular 22 drops Node 20 (`^22.22.3 || ^24.15.0 || ^26.0.0`).
- Node 20 is past end of life. Angular 21 still lists it, so this hop stayed on the oldest line both Angular 19.2 and Angular 20 allow.
- `ngx-cookie-service` **20.1.1** and `ng2-file-upload` **9.0.0** peer `^20`. They must be bumped with the next Angular major. `ng update` does not carry them. Cookie-service 21 and `ng2-file-upload` 10 peer Angular 21.
- `@ngbracket/ngx-layout` **16.1.3** and `ng2-charts` **5.0.4** peer `>=16`. They did not have to move for Angular 20. Confirm them again on the next hop before treating a newer major as required.
- The application builder was not adopted. The webpack builder is deprecated and still supported. `APP_INITIALIZER` was not replaced. The control-flow migration was offered and not run. `*ngIf`, `*ngFor`, and `*ngSwitch` are deprecated and still compile.
- The Material theme still uses the Material 2 helpers (`m2-define-light-theme` / `m2-define-dark-theme`), plus `mat.elevation-classes()` and `mat.app-background()`. The build warns that the theme is not the color/typography/density map, and that some Browserslist entries are outside Angular 20's browser support. Material 3 was not adopted. Competition admin, Dert of Derts, notifications, and system admin were not part of the layout pass.
- Standalone components, typed forms, and zoneless change detection were not adopted. The `standalone: false` flags stay until a later conversion. Angular 20 makes `zone.js` optional. This site stays on **0.15.1**. `moduleResolution` is `bundler`.
- `entryComponents` remains on `AppLoaderModule`. The commented dashboard chart still uses the Chart.js 2 inputs.
- These packages are still referenced and were left in place: `angular-csv-ext`, `hopscotch`, `perfect-scrollbar`, `moment`, `tslint`, `codelyzer`. TSLint-to-ESLint is separate work. `@ngx-translate/core` 14, `@ngx-translate/http-loader` 7, `@swimlane/ngx-datatable` 20.1.0, and `@auth0/auth0-angular` 2.2.3 still install because their peers are an open `>=` range.
