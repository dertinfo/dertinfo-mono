# Website upgraded from Angular 18 to Angular 19

## Summary of the work completed

The website (`apps/dert-web`) now builds and runs on Angular **19.2.25**, CLI **19.2.27**, and Angular Material / CDK **19.2.19**. The Ionic app is unchanged. `npm install` in `apps/dert-web/src/client` succeeds without `force`, and `npm run build:hosted` succeeds. The existing website smoke suite passed.

Nothing had to move before `ng update`. Node 18.20.8 and RxJS **6.6.7** were already inside the Angular 19.2 ranges. `ng update` moved TypeScript from **5.4.5** to **5.8.3** and `zone.js` from **0.14.10** to **0.15.1**. `ngx-cookie-service` moved from 18.0.0 to **19.1.2**, and `ng2-file-upload` from 7.0.1 to **8.0.0**, because those peers named Angular 18. `@ngbracket/ngx-layout` stayed at **16.1.3** and `ng2-charts` at **5.0.4**. Their peers are `>=16`, and the production build accepted them.

The optional application-builder and `provide-initializer` migrations were not run. The webpack `browser` builder stayed, and `APP_INITIALIZER` stayed. A required core migration added `standalone: false` to 225 NgModule components, directives, and pipes. The Material migration replaced `mat.core()` with `mat.elevation-classes()` and `mat.app-background()` in the five theme files. `tsconfig.json` `target` is still `es2020`.

The lockfile stays `lockfileVersion` 3. The Dockerfile's global CLI pin is `@angular/cli@19`. Host-tooling notes in `docs/technical/infra/configuration.md` now say the website CLI is 19 and that website `ng` needs Node `^18.19.1`, `^20.11.1`, or `>=22.0.0`.

## Why the work was completed

This is the fifth hop from Angular 14 toward a current Angular. The aim was the same as the earlier hops: one major, a healthy dependency tree, and the smallest application change that still installs and builds.

The 17 to 18 notes listed Node and RxJS as already inside the Angular 19 range, TypeScript 5.4.5 as too old, and `ngx-cookie-service` and `ng2-file-upload` as the peers that had to move with the major. Checked against the [version compatibility](https://angular.dev/reference/versions) table, that was right. There was no engine change to make on Angular 18 first. `ng update` moved TypeScript and `zone.js`.

The application builder, the `provideAppInitializer` rewrite, the new control flow, standalone conversion, typed forms, zoneless change detection, and Material 3 were left. Angular asks for the application builder during this update. The webpack builder is deprecated and still supported, so the prompt was declined. `*ngIf`, `*ngFor`, and `*ngSwitch` still work. Angular 20 is the hop that deprecates those three and runs the control-flow migration. The `standalone: false` flags are the migration that keeps today's NgModules working after the default flips to standalone. They are not a conversion.

## Issues that were encountered on the way

- This machine's default Node is 24. Update, install, `ng build`, and `ng serve` used a portable Node **18.20.8** (npm 10.8.2). The Angular CLI 19.2.27 engines field allows `>=22.0.0`, so Node 24 is inside that range. CI and the website image stay on Node 18. The Static Web Apps CLI on this machine is still the Node 24 global.
- `ng update @angular/cli@19 @angular/core@19` and `ng update @angular/material@19` completed with no `--force`. The second command needed `--allow-dirty` because the first update was not committed yet. The CLI listed `use-application-builder` and `provide-initializer` as optional migrations and did not run them. The webpack `browser` builder stayed. `APP_INITIALIZER` stayed.
- The core migration added `standalone: false` on 225 files. `pending-tasks` and the server bootstrap migration made no changes.
- `ngx-cookie-service` 18 peers `^18`, so it moved to 19.1.2. `ng2-file-upload` 7 peers `^18`. Version **8.0.0** peers `@angular/core` `^19` and does not peer `jest-preset-angular`. After that, `npm install` succeeded with no peer errors. `@ngbracket/ngx-layout` 16.1.3 and `ng2-charts` 5.0.4 peer `>=16` and stayed. The production build compiled them.
- The Material schematic replaced `mat.core()` in the five theme files. The `m2-` helpers stayed. The production build still warns that the theme is not the color/typography/density map.
- The Angular 19 schematic did not rewrite `tsconfig.json` `target`. It is still `es2020`. The CLI still prints that it applies ES2022 itself. Browserslist entries that need ES5 (`kaios 2.5`, `op_mini all`) are ignored. `entryComponents` is still set on `AppLoaderModule`. The build accepts it.
- The first smoke runs failed in event configure. Material 19 marks an unselected step `inert` and hides it. The header is selected before the body is visible, and a forced fill on that control does not update the form. The smoke helpers now wait until the control is visible. `PLAYWRIGHT_BROWSERS_PATH` pointed at an empty cache, so the suite used the Chromium already under `%LOCALAPPDATA%\ms-playwright`.

## References to any best practices that we found

- [Angular version compatibility](https://angular.dev/reference/versions) — Angular 19.2 supports Node `^18.19.1 || ^20.11.1 || ^22.0.0`, TypeScript `>=5.5.0 <5.9.0`, and RxJS `^6.5.3 || ^7.4.0`. Angular 20.0 supports Node `^20.19.0 || ^22.12.0 || ^24.0.0`, TypeScript `>=5.8.0 <5.9.0`, and the same RxJS range.
- [Angular v19](https://github.com/angular/angular/releases/tag/19.0.0) — components, directives, and pipes are standalone by default. `ng update` sets `standalone: false` on existing NgModule declarations.
- [Angular Material 19 theming](https://github.com/angular/components/issues/30055) — `mat.core()` is replaced by `mat.elevation-classes()` and `mat.app-background()`. `ng update` applies that split.
- [ngx-cookie-service 19.1.2](https://www.npmjs.com/package/ngx-cookie-service/v/19.1.2) peers `@angular/core` `^19`.
- [ng2-file-upload 8.0.0](https://www.npmjs.com/package/ng2-file-upload/v/8.0.0) peers `@angular/core` `^19`.

## Any remaining issues that we may wish to address

- Angular 20 drops Node 18. This site, its CI, and the website image are on Node 18. TypeScript **5.8.3** and RxJS **6.6.7** are inside the Angular 20.0 range. The next hop has to move Node before `ng update`.
- `ngx-cookie-service` **19.1.2** and `ng2-file-upload` **8.0.0** peer `^19`. They must be bumped with the next Angular major. `ng update` does not carry them.
- `@ngbracket/ngx-layout` **16.1.3** and `ng2-charts` **5.0.4** peer `>=16`. They did not have to move for Angular 19. Confirm them again on the next hop before treating a newer major as required.
- The application builder was not adopted. Angular asks for it on this hop. The webpack builder is deprecated and still supported. `APP_INITIALIZER` was not replaced. The new control flow was not adopted. Angular 20 deprecates `*ngIf`, `*ngFor`, and `*ngSwitch` and runs that migration during `ng update`.
- The Material theme still uses the Material 2 helpers (`m2-define-light-theme` / `m2-define-dark-theme`), plus `mat.elevation-classes()` and `mat.app-background()`. The build warns that the theme is not the color/typography/density map. Material 3 was not adopted. Competition admin, Dert of Derts, notifications, and system admin were not part of the layout pass.
- Standalone components, typed forms, and zoneless change detection were not adopted. The `standalone: false` flags stay until a later conversion. Angular 20 makes `zone.js` optional. This site stays on **0.15.1**.
- `entryComponents` remains on `AppLoaderModule`. The commented dashboard chart still uses the Chart.js 2 inputs.
- These packages are still referenced and were left in place: `angular-csv-ext`, `hopscotch`, `perfect-scrollbar`, `moment`, `tslint`, `codelyzer`. TSLint-to-ESLint is separate work. `@ngx-translate/core` 14, `@ngx-translate/http-loader` 7, `@swimlane/ngx-datatable` 20.1.0, and `@auth0/auth0-angular` 2.2.3 still install because their peers are an open `>=` range.
